# 使用说明

## 首次进入

按 [README](../README.md#快速开始) 启动本机演示后，打开 <http://127.0.0.1:3000>。默认演示身份可浏览样例项目和功能；样例公司、事件和金额均为虚构数据。团队环境请使用管理员创建的账号在 `/login` 登录。

## 投资经理的常见流程

1. 在“今日”查看本人项目、待处理事项和消息。
2. 在“发现项目”查看线索，核对原始来源、发布日期、公司名称与赛道。需要时手工上传原件建立候选。
3. 在候选详情记录核验意见；确认后转入正式项目，并指定负责人。
4. 在项目详情更新阶段与里程碑，上传资料、添加评论和补证请求。
5. 在“研究”发起任务，检查报告中的证据与未披露项，保留自己的人工判断。
6. 在“审批”提交事项并附相关资料，等待指定审核人处理。

## 审核人与管理员

- 审核人应阅读原件和批注，再决定通过、退回或要求修改；修改同一事项时留意版本冲突提示。
- 管理员在“人员管理”维护成员、部门和权限；账号创建通过私有 CLI 或内部流程完成，不开放自助注册。
- 信源管理员应先核对授权、robots/条款、允许域名和存储范围，再启用采集。采集失败及待解析候选可在 Source Ops 查看。

## 使用个人 AI

在“设置”选择服务商、模型并保存个人 API Key。项目中提问前，应确认该资料允许发送给所选模型。回答附来源链接；请以原件为准复核金额、日期、主体和推断。个人密钥和问答记录按账号隔离，切勿把密钥写在项目资料、聊天或 Git 文件中。

## 本机数据位置

默认业务数据库位于 `.data/vc-hunter.db`，认证模式的本机认证数据库默认位于 `.data/auth.db`；项目文件位于 `.data/project-documents/`。这些路径均被 Git 忽略。删除本机数据前，请先确认是否需要备份。生产环境应通过环境变量指定受限权限的持久化目录，并分别备份数据库和上传目录。

## 部署前检查

1. 使用 Node.js 22.5+，执行 `npm ci`、`npm run lint`、`npm run typecheck`、`npm test` 和 `npm run build`。
2. 配置 `VC_HUNTER_AUTH_ENABLED=true`、`VC_HUNTER_CURRENT_TENANT_ID`、`BETTER_AUTH_URL`、随机的 `BETTER_AUTH_SECRET`、独立的业务库和认证库绝对路径。
3. 使用 HTTPS 反向代理；应用端口只绑定本机或受控内网，不直接暴露在公网。
4. 在私有环境文件中保存模型密钥、加密材料和信源配置；限制文件权限，并建立轮换与备份机制。
5. 运行认证迁移、创建首个管理员，核对登录、退出、匿名拦截、权限和备份恢复。
6. 若运行后台 Agent，只启一个与当前 SQLite 工作空间相匹配的进程，并监控失败记录。

该清单用于准备环境，不代表任意云主机已通过生产安全验收。
